# RA workflow, stage 1: upload and Data Ingress intake

## Why this stage matters

This is the **trust and admission boundary** for Relationship Awareness (RA) data.  It turns an authenticated uploader's ZIP payload into a named, client-scoped, observable session and refuses to start downstream work until that session is explicitly committed.  In practical terms, it protects the rest of RA from three damaging ambiguities: who supplied the files, which files form one extract, and whether another RA run is already changing that client's relationship data.

The authoritative modern HTTP surface is `POST /api/public/v2/dataingress/v2/session`, followed by upload and commit endpoints ([pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs:40](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L40), [75](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L75), [93](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L93), [141](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L141)).  The controller comments identify RAHaUT as the expected caller for the V2 API ([26-38](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L26)).

## Uploaded files and effective schemas

### ZIP transport versus client files

The V2 upload unit is a ZIP envelope, or ordered chunks reconstructed into one. It enumerates non-directory entries and retains their base filenames; it does not compare those names to a global RA manifest. The API validates a readable, nonempty ZIP and an optional non-future extract date, then gives the envelope a generated name.

Actual source filenames, file formats, headers, joins, and source-to-contract mappings are client configuration. The application loads each client's file-join and server-mapping XML before mapping the uploaded file set. The configuration model supports CSV, delimited, and fixed-width files. Thus the repository cannot list a universal raw filename or source-column inventory.

Evidence: [ZIP entry enumeration](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Models/Request/ZipFileRequest.cs#L18), [envelope validation](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs#L20), [client configuration loading](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/RelationshipAwarenessBusinessService.cs#L524), and [supported file definitions](../../repositories/pl-application/PrecisionLender.DataImport.Mapping/Configuration/FileSetConfiguration.cs#L14).

| Logical upload category | Required status | Typed contract | Relationship linkage |
| --- | --- | --- | --- |
| Relationships | Client-configured; mapped result list is required | `ICoreRelationshipImport` | Supplies the relationship external identifier. |
| Loans | Client-configured; mapped result list is required | `ICoreLoanAccountImport` | `RelationshipExternalIdentifier` links loan economics to a relationship. |
| Deposits | Client-configured; mapped result list is required | `ICoreDepositAccountImport` | `RelationshipExternalIdentifier` links deposits. |
| Other accounts | Client-configured; mapped result list is required | `ICoreOtherAccountImport` | `RelationshipExternalIdentifier` links non-loan/deposit economics. |
| Loan and deposit associations | Client-configured; optional mapped lists | `ICoreLoanAssociationImport`, `ICoreDepositAssociationImport` | Link an account and relationship for ownership/association views. |
| Collateral positions | Client-configured; optional mapped list | `ICoreCollateralPositionImport` | Reaches a relationship through its loan linkage. |
| Loan fees and participations | Client-configured; supported mapping categories | `ICoreLoanFeeImport`, `ICoreParticipationImport` | Reach a relationship through the referenced loan. |

The required/optional labels above are deliberately not raw-file requirements: the commit boundary requires only one ZIP or chunk. The legacy serialized result contract marks relationship, loan, deposit, and other lists required, but association and collateral lists optional ([commit guard](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L264), [legacy mapped-result contract](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/MarginProCoreForPli/DTO/Integration/Import/ImportMappingResults.cs#L25)). The active mapping configuration nevertheless has all nine logical mapping categories ([MappingConfiguration.cs](../../repositories/pl-application/PrecisionLender.DataImport.Mapping/Configuration/MappingConfiguration.cs#L13)).

### Where each schema lives

| Layer | Effective contract | Why the distinction matters |
| --- | --- | --- |
| API envelope | `ZipFileRequest` and `UploadedZipFileModel` | It governs ZIP bytes, entry names, and extract date—not client relationship columns. |
| Client configuration | `FileJoinsConfiguration` plus `ServerMappingConfiguration` XML | This is the effective per-client source schema: physical files are joined and their columns mapped into RA types. |
| Typed inbound RA data | `ICoreRelationshipImport` and `CoreRelationshipImport`; related account/association contracts | This is the stable application-facing relationship import contract after raw columns are mapped. |
| Mapping validation | `MappingValidation` and indexed mapping results | It rejects/filters unsuccessful mappings and detects duplicate imported identifiers before transform. |
| RADAR DatabaseOutput | `DatabaseOutput/dbStagingRelationshipNew.csv` and other generated staging files | These are transform output, not upload files; application code reads this relationship output into SQL staging. |
| DI Primary | `RelationshipsMetaData` and `RelationshipsIngestion` | This is the downstream published Primary schema. It reads RADAR output and enforces the Primary schema, so it must not be used to infer inbound columns. |

The application reads `DatabaseOutput/dbStagingRelationshipNew.csv` only after the transform and bulk-loads records for the current RA run ([DataIngressPersistence.cs](../../repositories/pl-application/PrecisionLender.Application.Core/Persistence/DataLake/DataIngressPersistence.cs#L1730)). DI's Primary relationship contract separately declares `ExternalIdentifier` and `RaRunId` as its identity columns and includes hierarchy, pricing, owner, industry, and risk fields ([relationships.py](../../repositories/di-pipelines/ds-jobs/src/datascience_jobs/meta_data/datasets/primary/pl_relationship_awareness/relationships.py#L12), [relationships.py](../../repositories/di-pipelines/ds-jobs/src/datascience_jobs/jobs/primary_ingestion/ra/relationships.py#L10)).

### Important relationship fields

The inbound relationship contract is intentionally smaller than the downstream Primary record. `ICoreRelationshipImport` adds name, owner, VIP status, merge fields, raw mapped values, and run date to the inherited external identifier; the concrete DTO marks name, owner, VIP status, and row values required, while merge fields and run date are optional ([ICoreRelationshipImport.cs](../../repositories/pl-application/PrecisionLender.Common.Contracts/DTOs/RA/Contract/ICoreRelationshipImport.cs#L24), [CoreRelationshipImport.cs](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/MarginProCoreForPli/DTO/Integration/Import/CoreRelationshipImport.cs#L28)).

| Field | Role | Required/conditional evidence | Downstream consequence |
| --- | --- | --- | --- |
| `ExternalIdentifier` | Imported relationship identity and account join target | Required in inherited concrete import type; duplicate validation groups relationships on it. | Broken or duplicate values prevent trustworthy relationship/account grouping and conflict with Primary identity. |
| `ExternalIdentifierMasked` | Safe display/logging companion to identity | Required in inherited concrete import type. | Preserves an obfuscated identifier for downstream operational output. |
| `Name` | Relationship display identity | Required in `CoreRelationshipImport`. | Becomes the human-readable relationship label. |
| `OwnerUsername` | Imported owner/officer resolution input | Required in `CoreRelationshipImport`; wildcard handling is explicitly supported. | Enables owner attribution after user resolution. |
| `IsVIPRelationship` | Relationship classification | Required in `CoreRelationshipImport`, although nullable. | Retains VIP semantics through the import rather than inferring it later. |
| `MergeId`, `MergeName`, `MergeIdMasked` | Client-controlled merge/householding identity | Optional; `HasClientManagedMergeId` is true only when `MergeId` is populated. | Determines whether client household/merge intent can be carried into relationship handling. |
| `RunDate` | Source effective-date provenance | Optional on the import contract. | Associates imported data with a source run date; it is distinct from the API envelope extract date. |
| `RowValues` | Original mapped-column payload | Required. | Preserves client-specific mapped values without making every raw column part of the universal interface. |

Accounts are attached through their own `RelationshipExternalIdentifier`, and validation gathers relationship IDs from relationships, accounts, associations, collateral, and fees ([ICoreAccountImport.cs](../../repositories/pl-application/PrecisionLender.Common.Contracts/DTOs/RA/Contract/ICoreAccountImport.cs#L25), [MappingValidation.cs](../../repositories/pl-application/PrecisionLender.DataImport.Mapping/Validation/MappingValidation.cs#L497)). This join key is the practical reason the relationship identifier is the most important inbound field.

`TopLevelParent`, `ParentId`, `AssumptionSetId`, `IndustryCode`, `RiskRating`, and resolved `OwnerId` are important **downstream** fields in the Primary Relationships schema, but they are not properties of `ICoreRelationshipImport`. They must not be presented as universally required upload columns; the transform/enrichment path produces them after mapping ([Primary Relationships schema](../../repositories/di-pipelines/ds-jobs/src/datascience_jobs/meta_data/datasets/primary/pl_relationship_awareness/relationships.py#L49)). Their importance is nevertheless material: hierarchy controls roll-up, owner controls attribution, and assumption-set/risk/industry fields provide pricing and segmentation context.

## Chronological sequence: upload to accepted session

1. **Start.** The caller creates a session. The service determines an upload type from client RA settings, creates the blob-backed `SessionOpen` state, publishes `DataIngressSessionStarted`, and schedules automatic closure in 24 hours ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:197](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L197)-[239](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L239)). 2. **Upload a ZIP (or upload chunks).** For a direct ZIP, `ZipFileRequest` lists only file entries and strips directory paths; the mapper validates it, assigns a server-generated ZIP name, and supplies the extract date ([pl-application/PrecisionLender.Application.API.Shared/Models/Request/ZipFileRequest.cs:25](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Models/Request/ZipFileRequest.cs#L25)-[41](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Models/Request/ZipFileRequest.cs#L41), [pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs:10](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs#L10)-[18](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs#L18)). The business service accepts it only while `SessionOpen`, uploads it, records metadata and the maximum extract date, and publishes `DataIngressSessionFileUploaded` ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:504](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L504)-[530](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L530); [pl-application/PrecisionLender.Application.Core/Persistence/DataLake/DataIngressPersistence.cs:100](../../repositories/pl-application/PrecisionLender.Application.Core/Persistence/DataLake/DataIngressPersistence.cs#L100)-[131](../../repositories/pl-application/PrecisionLender.Application.Core/Persistence/DataLake/DataIngressPersistence.cs#L131)). ## Validation, safety, and idempotency

- **Session-state validation:** direct upload only permits `SessionOpen`; commit repeats that check and rejects empty input ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:254](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L254)-[270](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L270), [507-514](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L507)).
- **Concurrency/idempotency:** session-state updates take an exclusive blob lease ([pl-application/PrecisionLender.Common.Storage/Access/Blob/DataIngressFilesetContainer.cs:55](../../repositories/pl-application/PrecisionLender.Common.Storage/Access/Blob/DataIngressFilesetContainer.cs#L55)-[73](../../repositories/pl-application/PrecisionLender.Common.Storage/Access/Blob/DataIngressFilesetContainer.cs#L73)); the running marker uses atomic create-if-absent. Repeated abort is explicitly idempotent ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:440](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L440)-[458](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L458)).
- **Important boundary:** this is not proof that each CSV’s schema or rows are valid. ZIP/container validity and timing are validated here; mapping and domain validation occur later. This is an inference from the input validator’s limited checks and the process manager’s later file/run validation phases ([pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs:20](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs#L20)-[27](../../repositories/pl-application/PrecisionLender.Application.API.Shared/Mapping/ApiV2/DataIngressMapping.cs#L27), [pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs:126](../../repositories/pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs#L126)-[152](../../repositories/pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs#L152)).

## Failure modes and observability

- The public API returns `404` for an unknown session, `409` for non-open/aborted/empty commit, and `500` when the service records an exception ([pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs:106](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L106)-[122](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L122), [216-233](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L216)).
- A session left open longer than 24 hours is automatically changed to `Aborted` with an explanatory message ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:3217](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L3217)-[3234](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L3234)).
- A competing run aborts the attempted session, preserves a client-facing reason, and emits a processing-error notification ([pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs:275](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L275)-[284](../../repositories/pl-application/PrecisionLender.Application.Core/Business/Direct/RA/DataIngressBusinessService.cs#L284)).
- Commit-handler failures remove the running marker, report an error, retry with 1/3/9/27-minute backoff, then publish `DataIngressJobFailed` after retry exhaustion ([pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs:203](../../repositories/pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs#L203)-[233](../../repositories/pl-application/PrecisionLender.Application.CQRS.Core/ProcessManagers/DataIngress/DataIngressProcessManager.cs#L233)).
- Operators/callers can query session and file status; file status intentionally conflicts until the session is committed ([pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs:264](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L264)-[284](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L284), [315-341](../../repositories/pl-application/PrecisionLender.Application.Web/APIControllers/Public.V2/PublicDataIngressApiController.cs#L315)).

## Handoff contract to orchestration

The stage finishes once a `CommitDataIngressSession` command has successfully caused `DataIngressFileCommitted` to be published.  The event carries:

- `DataIngressRequestId` — client + session/run correlation;
- `UploadedZipFiles` — accepted upload metadata;
- `ClientName` — operational context; and
- `RequestPath` — the Data Lake request location derived from the commit timestamp ([pl-application/PrecisionLender.Common.Contracts/DTOs/DataIngress/DataIngressResponseDTO.cs:15](../../repositories/pl-application/PrecisionLender.Common.Contracts/DTOs/DataIngress/DataIngressResponseDTO.cs#L15)-[22](../../repositories/pl-application/PrecisionLender.Common.Contracts/DTOs/DataIngress/DataIngressResponseDTO.cs#L22)).
